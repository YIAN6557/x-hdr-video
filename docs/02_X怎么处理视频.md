# X 怎么处理视频

所有数据都是 2026-10-31 和 11-01 从 X 实际下发的文件里查的：用公开的 [fxtwitter](https://github.com/FixTweet/FxTwitter) 接口（`https://api.fxtwitter.com/status/<帖子ID>`）拿到每个清晰度的 mp4，再用 ffprobe 读色彩标记、读码流里的编码器信息。`tools/check_x_video.sh` 就是把这个过程写成了一条命令。

## X 会把每个视频都重新压一遍

每个文件的码流里都有编码器留下的参数。压缩参数在所有账号上都一样（但处理程序有两套，见下一节）：

| 清晰度 | 编码器 | 质量 | 码率上限 |
|---|---|---|---|
| 1080p | libx264 | CRF 23 | 约 10 Mbps |
| 720p | libx264 | CRF 28 | 约 2 Mbps |

一般还会再出 270p 和 360p。没有哪个文件是原样转发的，所以 X 发出去的色彩标记，完全由 X 的转码程序决定。

## 确切原因：X 有两套视频处理程序（11-01 查清）

X 处理完的每个 mp4 里，都写着处理它的程序的名字（mp4 的 handler name）。一共有两套：

| | 新程序 | 旧程序 |
|---|---|---|
| 文件里写的名字 | `X-Qaptuur muxer` | `Twitter-vork muxer` |
| x264 版本 | core 165 | core 164 |
| mp4 兼容品牌 | `isomiso2avc1mp41` | `isomiso4` |
| 播放列表里的编码字符串 | 小写，比如 `avc1.64001f` | 大写，比如 `avc1.64001F` |
| 色彩信息 | **会读**：H.264 8 位 HLG 保留，其他 HDR 转成 bt709 | **完全不读**：所有色彩标记都丢掉 |

压缩参数两套一样，只有对色彩的处理不同。

我们把下载过的视频文件（来自 17 个账号，包括普通视频）按处理程序和色彩标记统计，129 个能认出程序：

| 处理程序 | 文件数 | HLG | bt709 | 没有标记 |
|---|---|---|---|---|
| 旧的 Twitter-vork | 79 | 0 | 0 | **79** |
| 新的 X-Qaptuur | 50 | 24 | 20 | 6 |

旧程序处理的视频，一个色彩标记都没有；所有保留了 HLG 的视频，都是新程序处理的。新程序里"没有标记"的 6 个，多半是原片本来就没有色彩标记。

**每个账号走哪套程序是固定的，X 在一个一个地把账号迁到新程序上：**

| 账号 | 换到新程序的时间（从发过的视频看） |
|---|---|
| @naundob | 10-04 之后的视频全部是新程序 |
| @banbudev | 10-12 之后 |
| @SpaceX | 10-20 到 10-25 之间 |
| @hi_personality | 10-21 到 10-22 之间 |
| @MinLiBuilds | 查到的 15 条（10-25 起）全部是新程序 |
| @NASA、@XCreators | 10-28、10-29 已经是新程序 |
| @EianLu（我们）、@gnarco、@xiayitiaoAI、@vbar_io、@danielbeanpole | 到 10-31 还是旧程序 |
| @OpenAI、@MKBHD、@BBCWorld | 到 10-29 – 10-30 还是旧程序 |

**网页版没有 HDR 开关。** 我们登录网页版看过：1513 个功能开关里没有一个和 HDR 有关；上传视频时网页只发文件大小、文件类型、视频时长和类别（发帖的视频一律是 `amplify_video`），完成上传时只发 media_id、是否异步处理和文件的 md5，完全没有提 HDR。所以走哪套程序是 X 服务器按账号定的，用户这边没有办法切换。

**查一个账号在哪套程序上，不用发 HDR 测试帖**，看它以前发过的任何一条视频就行：

```bash
zsh tools/check_account.sh 用户名
```

## 三种结果

| X 下发的标记 | 意思 | 在手机上 |
|---|---|---|
| `arib-std-b67` / `bt2020` | **保留了 HLG** | 按 HDR 播放，会发光 |
| `bt709` / `bt709` | X 读到了 HDR，**转成了普通视频** | 颜色正常，不发光 |
| 没有标记（ffprobe 显示 `unknown`） | X **没读**文件里的色彩信息 | 把 HLG 信号当普通视频播，颜色发灰发淡 |

注意：普通视频本来就没有标记的话，X 发出去也是"没有标记"，这是正常的。只有上传的文件带了 HLG 标记、X 却发回"没有标记"，才说明 X 丢掉了它。

## 另一种失败：X app 的「数据节省」模式

@naundob [发现](https://x.com/naundob/status/2116573031393046911)：在 X app 里打开"数据节省"以后，他的号也发不出 HDR 了。我们查了他开着数据节省发的 [HDR Test 7](https://x.com/naundob/status/2116571937644466421)：

- 和他之前成功的是同一段素材（8.27 秒），这次 X 下发的文件**最高只有 720p**，标记是 **bt709**。
- 看起来是 X app 在手机上先把视频压成 720p 的普通视频再上传，X 收到的已经不是 HDR 了。

这和我们的号失败的样子不一样：

| | 数据节省开着（@naundob Test 7） | 我们的号 |
|---|---|---|
| 最高清晰度 | 720p | 1080p |
| 色彩标记 | bt709 | 完全没有 |
| 画面 | 转成了普通视频 | 数值没变：X 收到的是原文件，只是把标签丢了 |
| 电脑浏览器发 | 不受影响（这是 X app 里的设置） | 也失败 |

我们的号数据节省本来就是关着的；第 5 次用 X app 发的那条也有 1080p，如果当时开着数据节省，最高应该只有 720p。所以数据节省不是我们失败的原因。

如果你用 X app 发，结果是"最高 720p + bt709"，先查这个设置：X app → 设置和隐私 → 无障碍、显示和语言 → 数据使用 → 数据节省，关掉再发。

## 从表里能看出什么

**1. 格式决定"保留"还是"转成普通视频"。**
@naundob 第 3 次和第 4 次的视频都是 8.27 秒、30 帧；第 1、2 次和第 5 次都是 59.38 秒、60 帧。时长和帧率完全一样，很可能是同一段素材，只换了格式就从 bt709 变成了 HLG。@banbudev 也明确说第 2 条是"同一段 AI 视频换成 H.264 + HLG 编码"。所以在能用的账号上：

- H.264 8 位 HLG → 保留
- 杜比视界、HDR10、iPhone 原生 HDR → 转成普通视频
- HEVC → 转成普通视频（@banbudev 的经验）

**2. 账号决定"会不会读"。**
能用的账号，换格式会得到 bt709 或 HLG，说明 X 每次都读了色彩信息；不能用的账号，不管传什么，都是"没有标记"。两组账号失败的方式不一样，这是最关键的区别。原因就是上面说的两套处理程序。

**3. 同一个文件，换个账号就不行。**
@xiayitiaoAI [说](https://x.com/xiayitiaoAI/status/2116411841375277511)，他把原博主在 X 上的视频下载下来（文件里有 HDR），原样重新上传，到他的号上就变成了普通视频。这是他自己的描述，我们没有复现。

**4. 不是运气，也不是时间。**
- 在能用的账号上，结果是固定的：@banbudev 换格式后 8/8，@hi_personality 9/9。
- 在不能用的账号上，结果也是固定的。
- 成功和失败在时间上是交错的：10-31 04:20–04:41 @danielbeanpole 连发 3 条都失败，而 @banbudev 在 04:05 和 05:07 发的都成功。所以不是 X 在某个时间统一打开或关闭了这个功能。

## 跟账号的什么有关（已查清）

跟账号本身的属性无关，只看 X 有没有把这个账号迁到新的处理程序（见上面「确切原因」）：

| 以前的猜测 | 结果 |
|---|---|
| X 在做灰度测试 | **对**：具体是把账号从旧程序 Twitter-vork 迁到新程序 X-Qaptuur |
| 会员等级 | 不是：我们的号是会员（能上传长视频），还在旧程序上 |
| 地区 | 不是：我们在美国，还在旧程序上；德语、中文账号都有在新程序上的 |
| 粉丝数 | 不是：@OpenAI、@MKBHD 这样的大号到 10 月底也还在旧程序上 |
| 是否认证、账号新旧 | 不是：两边都有 |

X 按什么顺序迁移，从外面看不出来。

## 为什么不能把 HDR "固定"在画面里

视频里每个像素只是一个 0–255 的数字（8 位）。同一个数字 235：

- 按普通视频（BT.709）的规则播，就是界面白那么亮；
- 按 HLG 的规则播，手机会把它推到界面白的好几倍。

"按哪种规则播"写在色彩标记里。X 重新压缩以后，文件里写什么由 X 决定。我们的第 3 次测试里，X 原样保留了画面数字，但没写标记，手机就按普通视频播。普通视频最亮只能到界面白，超过界面白的"发光"做不出来。
